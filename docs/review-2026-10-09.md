# Review disposition — 2026-10-09

This change addresses the external review of the code released as v0.1.0.
The release tag and published archive are unchanged. Findings below refer to the
review's F01–F15 identifiers, not a certification of general MCP compliance.

| Finding | Decision and implementation |
| --- | --- |
| F01 — phase ordering | Fixed. Public `access` prepares context only; `before_proxy` produces responses. Native lower-priority access denial and higher-priority before_proxy denial are tested for initialize, list and cold operation, with zero upstream calls. before_proxy policies must precede priority -500. |
| F02 — aggregate bounds | Fixed for encoded retention. Shared per-request byte and entry debits span discovery servers, pages and kinds, including cold routing and filtered entries. Public list size includes the JSON-RPC envelope. Oversized serialized ownership snapshots are not cached. Limits are not exact Lua heap/RSS bounds. |
| F03 — URI templates | Fixed with a deliberately restricted profile: 4096 bytes, 16 distinct expressions, reserved delimiters, no repeated or adjacent expressions. Patterns use no captures. More general RFC 6570 support is deferred. |
| F04 — empty SSE primers | Fixed. Empty data events, ID/retry fields and comments are ignored; nonempty malformed JSON still fails. Fragmented CR/LF/CRLF and multiline framing remain supported. No resumption is claimed. |
| F05 — schema exceptions | Fixed. Configuration/server types are checked before alias normalization. A real APISIX route invokes the schema checker with boolean, number, string and JSON null servers and verifies validation failure without exceptions. |
| F06 — tracing/cache identity | Retained conservatively. Every forwarded header still participates in the fingerprint. Omitting headers safely needs an explicit upstream policy contract, not a universal claim that tracing cannot affect authorization. Different trace IDs can cause a cache miss; existing token/tenant isolation tests remain. |
| F07 — catalog TTL | Fixed. Each kind keeps an absolute expiry; tools refresh does not extend prompts. Resources require both resource and template snapshots to be current. |
| F08 — SSE overhead | Partially addressed. Fragment storage coalesces into at most 1 KiB pieces, and event limits count inserted newlines. One-byte reads remain: the Content-Length early-progress test requires delivery before the final response exists. No throughput or RSS improvement is claimed without a benchmark. A new socket reader is deferred. |
| F09 — body/buffering | Disk-spooled and chunked request bodies now use bounded `core.request.get_body`, retaining the private JSON codec. Request-local `disable_proxy_buffering` was trialled with its required plugin enabled, but failed native mTLS and certificate-rotation tests on APISIX 3.19. Its named location differs from the normal TLS proxy path. Keep server-level buffering off until that path is fixed and verified. Other REST routes share this operational setting. |
| F10 — deadline/admission | Added `timeouts.request_total`, shared across queueing, discovery, initialization and operation; per-server budgets cannot extend it. Socket timeout is recalculated after connect. Checks occur at transport phase/read boundaries, not through an independent wall-clock interrupt inside the HTTP header parser. A separate public admission controller is deferred; use native APISIX admission policies. Internal concurrency alone does not bound waiting public requests. |
| F11 — diagnostics | Added sanitized upstream ID, protocol method, transport phase and HTTP failure status to warning logs, including failures after SSE begins. No credentials, tickets, arguments or results are logged. Full metrics, cache statistics, registered log variables and parent/bridge correlation are deferred. |
| F12 — numeric transparency | Documented the actual double/16-significant-digit contract and independently verified safe-integer, beyond-safe-integer, decimal and exponent behavior using the pinned OpenResty runtime. Arbitrary precision or lexical preservation would require a separate parsing design; do not merely raise cjson precision. |
| F13 — errors/profile | Fixed upstream 504 preservation, media-type case/whitespace normalization and Origin precedence over method rejection. Documented that acknowledged cancellation is not active cancellation. Existing stateless revision and unsupported features remain explicit. |
| F14 — native tests | Extended the existing real APISIX suite with phase composition, aggregate bounds, spooled/chunked bodies, schema and TTL regressions. Existing OIDC, IP policy, generation change, native TLS/mTLS and Java server tests remain. A native Test::Nginx/Admin API/PluginConfig matrix and new real-client lifecycle certifications are separate work, not claimed here. |
| F15 — operations/distribution | Updated installation prerequisites and request-body guidance. Existing deterministic GitHub release archive/install tests remain the distribution check. LuaRocks, Helm and a versioned atomic installer are not necessary to fix these runtime findings and are deferred. |

## Verification scope

Tests run against the APISIX 3.19.0 image pinned by digest in `compose.yaml`,
including its OpenResty/LuaJIT runtime. The integration suite exercises actual
HTTP traffic with two workers and two gateway instances. Python and Java are
fixtures only; installed runtime code remains pure Lua.

Run `bash scripts/style.sh`, `bash scripts/test.sh` and
`python3 tests/package.py`. The test runner prints the checked-out commit and
runtime version so CI evidence can be tied to the change. The reviewed fixes are packaged as 0.1.1; production rollout and client
verification remain separate from the fixture evidence.
